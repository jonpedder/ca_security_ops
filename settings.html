Mission Insights operator guide

Mission Insights is an authenticated Watch Center application for monitoring operational alerts, evaluating their location and severity, and managing incident review through ArcGIS Workflow Manager. It combines the live alert queue, an ArcGIS map, situational summaries, and a controlled triage and approval process.

Operational purpose: use the app to identify alerts that may affect monitored areas, establish an initial priority and workflow status, document what was reviewed, and route significant incidents for an approval decision.

Primary pages

  • Operations Map: discover, filter, map, and initially triage incoming alerts.
  • Incident Approval: review Workflow Manager jobs and record an approval disposition.
  • Settings: adjust presentation, labels, symbols, timing, and open this guide.

Workflow Manager is the authoritative system of record. Notes and structured audit events are attributed to the signed-in ArcGIS user.

Using the Operations Map

  1. Filter the incident queue. Use the age selector, search box, and severity, category, and source filters to reduce noise.
  2. Select an alert. Choose a queue card or a map symbol. The selected alert's details appear in the Intelligence Summary panel.
  3. Validate context. Review severity, source, location, watch area, start time, and description. Use Zoom to inspect map context and Source to open the originating alert.
  4. Decide whether to triage. Only alerts explicitly updated in the Incident triage section become Workflow Manager jobs and appear in Incident Approval.

How to initially triage an incident

Before updating: confirm that the alert is relevant to an operational watch area and that the source, location, and event description support the proposed priority.
  1. Select the incident from the queue or map and read the full description.
  2. Verify the source. Open the source link when available. Look for corroboration, recency, specificity, and signs that the alert is a duplicate or stale.
  3. Check location and impact. Use Zoom and the map to confirm proximity to monitored areas, facilities, transportation routes, or population centers.
  4. Set priority. Use Critical for immediate or potentially catastrophic operational impact; High for serious and time-sensitive impact; Medium for credible events requiring monitoring; and Low for limited impact or awareness-only items.
  5. Set workflow status. Use New or Ready for an initial handoff, In Progress while actively investigating, Pending when ready for review, and On Hold when blocked or awaiting information.
  6. Add a useful note. Record what was verified, the expected operational effect, uncertainties, and the recommended next action. Do not paste sensitive information that is not authorized for the system.
  7. Select Update incident. The app creates or updates the Workflow Manager job, claims its current step when needed, and writes append-only audit entries.
  8. Confirm the save. Wait for the green confirmation. Use Audit trail to verify the recorded changes or Incident PDF for a report.

Suggested first-note format

Verified: source and time checked. Impact: affected area/assets and urgency. Unknowns: information still needed. Recommendation: monitor, investigate, or send for approval.

How to use Incident Approval

  1. Open Incident Approval from the header. Sign in if prompted.
  2. Find the job. Search by incident ID, name, location, status, assignment, or priority. Persona and status filters narrow the queue.
  3. Select a triaged incident. Review the status, priority, current workflow step, alert ID, watch area, location, assignment, and description.
  4. Review history. Read prior triage and approval events before making a decision. If information appears stale, use Reload.
  5. Choose a decision and priority. Confirm that the selected priority still reflects the latest known operational impact.
  6. Write an approval note. A note is required. State the evidence considered, rationale, conditions or follow-up, and any remaining uncertainty.
  7. Select Record decision. Wait for “Decision saved.” The change is attributed to your signed-in account and appended to the audit history.

Rejecting or returning incidents

ApproveSets status to Approved. Use when the incident and proposed handling are supported and may proceed.
Return to triageSets status to Revised. Use when facts, priority, location, or recommended action need correction or more investigation.
Reject and closeSets status to Closed. Use for invalid, duplicate, irrelevant, stale, or otherwise non-actionable incidents.
Keep pendingLeaves the incident Pending. Use when a decision cannot yet be made and identify exactly what is awaited.

Return to triage (Revised)

  1. Select Return to triage when the incident may still be actionable but the record is incomplete or inaccurate.
  2. Set the best currently supported priority; do not preserve an inflated priority merely because it was submitted that way.
  3. In the required note, identify each correction needed, the evidence or verification required, and who should act next.
  4. Select Record decision, wait for confirmation, and verify that the history shows a change to Revised.

Example note: Returned for location confirmation and source corroboration. Current report conflicts with mapped coordinates. Triage analyst should verify the affected facility and attach or cite a second source before resubmission.

Reject and close (Closed)

  1. Select Reject and close only when no further triage or approval action is warranted.
  2. Confirm the incident is invalid, duplicate, outside scope, stale, or otherwise non-actionable.
  3. State the specific rejection reason and, for duplicates, reference the retained incident ID when known.
  4. Record the decision and verify the Closed status in the queue or audit history.

Example note: Rejected as duplicate of ALERT-12345. The retained incident contains the current source material and operational updates; no separate action is required.

Do not reject simply because information is incomplete. If the event may be relevant and can be corrected or corroborated, return it to triage instead. Closed records remain in the authoritative history.

Troubleshooting common approval errors

Approval note is requiredEnter a clear decision rationale in Approval note. Blank notes cannot be submitted.
Workflow Manager unavailableCheck network access and ArcGIS sign-in, then use Refresh. If the outage persists, preserve your note and contact the administrator.
Token expired / unauthorizedSign out and sign in again with an account authorized for this workflow item and role.
Unable to claim or update stepThe step may be assigned to another user or your account may lack the required Workflow Manager role. Reload before retrying.
Incident changed while reviewingSelect Reload, re-read the latest status and history, and make a new decision against the current record.
Decision appears not to saveWait for “Decision saved.” Do not repeatedly click. Refresh the queue and inspect history before submitting again.
Incident missing from the queueClear search and persona filters, select All statuses, and Refresh. Confirm initial triage created a job from the current template.
PDF does not downloadAllow downloads for the site, retry once, and verify the browser PDF/download policy. The workflow record is unaffected.
Safe retry sequence: copy your note, reload the incident, inspect the latest history, retry once, and escalate persistent errors with the incident ID, job ID, time, signed-in username, and exact message. Never include access tokens in a support request.

Audit trail and reports

  • Audit trail: opens the complete incident history with local time, user, event, changed values, and notes. Audit records are append-only in the app.
  • Incident PDF: creates a single-incident triage report with workflow state and history.
  • Triage PDF: on Incident Approval, creates a report of active triage jobs.
  • CSV / JSON: available in the Operations Map audit dialog for detailed analysis or transfer to an approved records process.

Always verify the report's incident ID, generation time, and signed-in user before distributing it. Follow organizational handling and retention rules.

Configuration settings

The Configuration tab changes the app's browser-stored presentation settings. You can customize status colors, persona names, incident symbols, button labels, ticker speed, and alert refresh frequency.

  • Save settings applies the current draft. Other open app pages update automatically.
  • Discard changes reloads the last saved settings.
  • Reset to base defaults removes all custom settings.
  • Export / Import template transfers configuration as JSON for review and reuse.
Note: presentation settings do not change Workflow Manager status membership, permissions, source services, or the authoritative workflow data.

Quick reference checklist

  • Confirm you are signed in as the correct user.
  • Filter by recent, relevant alerts.
  • Open and assess the source.
  • Confirm map location and watch area.
  • Check for duplicate incidents.
  • Assign a defensible priority.
  • Use a status that matches the handoff.
  • Write a clear triage or approval note.
  • Wait for the saved confirmation.
  • Verify the audit trail when the decision is significant.

If a save fails: keep your note text, check connectivity and sign-in state, reload the incident, confirm it was not updated by another operator, and retry once. Escalate persistent Workflow Manager errors to the application administrator.
